## 1. Introduction

본 문서는 Conceptualization 단계의 문서에 이어지는 Analysis 단계의 문서다.

### 1.1 Summary

음악을 즐기는 사람들은 특정 날짜에 들었던 음악과 그 당시의 감상을 기억하고 싶어한다. 그러나 기존의 음악 스트리밍 서비스는 단순한 재생 기록만 제공할 뿐, 개인적인 코멘트나 날짜별 기록 기능을 충분히 지원하지 않는다.

따라서 본 문서에서는 사용자가 Spotify API를 통해 음원을 검색하고, 날짜별로 음원을 기록하며 개인적인 코멘트를 남길 수 있는 음악 다이어리 서비스 MusicJournal을 제안한다. 이 서비스를 통해 사용자는 자신만의 음악 기록을 관리하고 청취 통계를 확인할 수 있을 것으로 기대한다.

### 1.2 Business Goals

- 사용자가 날짜별로 음원을 기록하고 개인 코멘트를 작성할 수 있어야 한다.
- 사용자가 Spotify API를 통해 원하는 음원을 키워드로 쉽게 검색할 수 있어야 한다.
- 사용자가 자신의 기록을 조회, 수정, 삭제할 수 있어야 한다.
- 사용자가 자신의 음악 청취 패턴을 통계로 확인할 수 있어야 한다.
- 회원가입 및 로그인을 통해 개인화된 서비스를 제공해야 한다.

### 1.3 Technical Goals

- Spotify Web API를 통해 음원 메타데이터(제목, 아티스트, 앨범, 앨범 커버 등)를 정확히 가져올 수 있어야 한다.
- JWT 기반 인증으로 사용자 세션을 Stateless하게 관리해야 한다.
- Spring Security를 통해 인증/인가가 적용된 안전한 API를 제공해야 한다.
- RESTful API 설계 원칙을 준수하여 확장 가능한 구조를 갖춰야 한다.
- 시스템의 응답속도는 사용자에게 불편함을 주어서는 안 된다.

**1) User**

시스템의 사용자 정보를 관리하는 핵심 도메인 클래스다. 이메일(email), 암호화된 비밀번호(password), 닉네임(nickname)을 보관한다. 모든 기록(Record)은 User에 종속된다.

**2) Record**

사용자가 날짜별로 기록한 음악 항목이다. User와 연관되며, 기록 날짜(date), 개인 코멘트(comment), 그리고 Spotify에서 가져온 Track 정보를 포함한다. 사용자의 음악 다이어리의 핵심 단위다.

**3) Track**

Spotify API에서 제공하는 음원 정보를 나타내는 클래스다. Spotify Track ID(spotifyTrackId), 음원 제목(title), 아티스트명(artist), 앨범명(album), 앨범 커버 이미지 URL(albumImageUrl)을 포함한다. Record에 종속되는 값 객체(Value Object)로 관리되며, 별도의 DB 테이블로 저장되거나 Record에 임베딩된다.

**4) SpotifyApiClient**

Spotify Web API와의 통신을 담당하는 클래스다. 키워드 기반 음원 검색 요청을 Spotify API에 전달하고, 응답으로 받은 Track 목록을 파싱하여 반환한다. 인증에 필요한 Spotify Access Token을 관리한다.

**5) JwtProvider**

JWT 토큰의 생성, 검증, 파싱을 담당하는 클래스다. 로그인 시 Access Token과 Refresh Token을 생성하고, 매 요청마다 Access Token의 유효성을 검증한다. 비밀 키(JWT_SECRET)는 환경 변수로만 주입받는다.

## 5. Glossary

| 용어 | 설명 |
|:---|:---|
| Spotify API | 음원 검색 및 데이터를 제공하는 외부 API |
| Track | Spotify API에서 제공하는 개별 음원 단위 |
| MetaData | 음원에 대한 부가 정보 (아티스트, 앨범, 장르 등) |
| Record | 사용자가 날짜와 코멘트를 함께 등록한 음악 기록 단위 |
| JWT | JSON Web Token. 사용자 인증 정보를 담은 토큰으로, 서버에 상태를 저장하지 않는 Stateless 인증 방식에 사용된다 |
| Access Token | 짧은 유효기간을 가진 JWT. API 요청 시 인증 수단으로 사용된다 |
| Refresh Token | 긴 유효기간을 가진 JWT. Access Token 재발급에 사용된다 |
| Stateless | 서버가 클라이언트의 세션 상태를 저장하지 않는 방식 |
| Value Object | 식별자 없이 속성 값으로만 동일성을 판단하는 도메인 객체 |
